## 发现并修复的问题

### 1. 旧栈陈旧容器（启动时）
Docker Desktop 开机自启了重组前 `docker/docker-compose.yml`（已移走）残留容器，postgres 崩 exit 127、backend 反复重启。→ 清掉旧 agenthub 容器，用当前 `src/docker/` 全新重建解决。

### 2. celery_worker 被标 unhealthy（已修）
- **根因**：celery_worker 复用 backend 镜像，继承了 Dockerfile 的 HTTP 探针（`curl localhost:8000/health`），但 celery 进程不跑 HTTP → 探针必失败。worker 本身功能正常（日志 `ready`、连上 broker）。
- **修复**：compose 给 celery_worker 加专属 healthcheck `celery -A ... inspect ping -t 8`。
- **踩坑**：首版用 `-d celery@$$HOSTNAME` 指定节点，但 CMD exec 形式**不展开 `$HOSTNAME`**（被当字面串）→ exit 69 No nodes replied。改为不带 -d（ping 所有 worker，任一回应即健康）+ `-t 8`（给 broker 往返留时间，避免默认 1s 超时）。
- 验证：容器内手动 `inspect ping` → `celery@... OK / pong / 1 node online`；start_period 后状态转 **healthy**。
