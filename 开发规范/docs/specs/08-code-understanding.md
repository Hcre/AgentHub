# BDD 规格: 代码理解与知识图谱规范

> 对应 `08-code-understanding_代码理解与图谱规范.md`（v2.0：§2.9 工具链增强的细化，收拢 01/02/05/06 调用图内容）

---

## 功能：代码理解与知识图谱规范文档

### 场景 1：声明细化环节与启用门槛
- 前置条件：无
- 操作步骤：
  1. 打开 `08-code-understanding_代码理解与图谱规范.md`
  2. 阅读开头引言
- 预期结果：
  - 声明细化「第二步 §2.9 工具链增强」
  - 声明收拢 01/02/05/06 调用图内容，是其唯一权威
  - 明确启用门槛：仅中大型项目（> 10 模块 或 > 5 万行），小项目不引入
  - 声明性能/召回率数据引用 docs/research/，不在规范内固化数字

### 场景 2：核心概念清晰可执行
- 前置条件：无
- 操作步骤：
  1. 阅读 §一核心概念
- 预期结果：
  - 6 种节点类型（FUNCTION/CLASS/MODULE/API/CONFIG/SCHEMA）
  - 12 种关系，分「静态可抽（基础层）/ 需语义分析（增强层）」两类

### 场景 3：图谱构建有明确方案
- 前置条件：理解概念后
- 操作步骤：
  1. 阅读 §二构建
- 预期结果：
  - 基础层静态分析 + 增强层 LLM 的混合策略
  - 增量优于全量；收束节点全量重建兜底
  - 不出现固化的资源节省百分比（如有，须标「见调研报告」）

### 场景 4：图查询与缺陷检测可执行
- 前置条件：图谱已构建
- 操作步骤：
  1. 阅读 §三查询与分析
- 预期结果：
  - 变更影响分析含 Cypher 上游查询 + 四步流程
  - ≥ 3 种缺陷检测模式含 Cypher + 风险等级（循环依赖/未用函数/上帝类/跨层违规）
  - 跨层违规 / 循环依赖与 01 架构红线对应
  - 不出现固化的检测准确率数字（不再出现「91.2% / VulGraph」）

### 场景 5：存储与工具选型按规模
- 前置条件：技术选型
- 操作步骤：
  1. 阅读 §五选型
- 预期结果：
  - 3 档存储（SQLite+FTS5 / KuzuDB / Neo4j）按行数选
  - 推荐工具标注「数据见调研报告，不固化」
  - 不强制列举特定工具数量，不再断言固定准确率/F1 阈值

### 场景 6：收拢的调用图内容齐全
- 前置条件：读者从 01/02/05/06 跳转而来
- 操作步骤：
  1. 阅读 §三/§四/§六
- 预期结果：
  - 含代码标注（@entrypoint/@callers/CALL_GRAPH）
  - 含影响分析驱动的增量测试
  - 含代码地图 CODE_MAP（全景 + 调用关系 + 关键入口）
  - 含依赖黑洞 / 孤儿模块检测

### 场景 7：检查清单可操作
- 前置条件：图谱实施中
- 操作步骤：
  1. 逐项核对 §八检查清单
- 预期结果：
  - 首项即「项目规模达门槛才引入图谱」
  - 覆盖构建 / CI 缺陷检测 / 影响分析 / 维护 / CODE_MAP
  - 不少于 8 项
