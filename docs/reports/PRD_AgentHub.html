§1 概述

产品概述

IM 聊天式多 Agent 协作平台 — 用户通过类飞书聊天界面与 AI Agent 对话，支持单聊、群聊（@mentions 多 Agent 协作）、任务自动分解与并行调度。

💬 类 IM 交互

用最自然的聊天方式调度 AI Agent，无需学习命令行或 API

🤝 多 Agent 协作

群组内协调者自动分解任务、分配 Agent、合并结果

🎨 富媒体产物

代码 Diff、网页预览、文件附件直接在聊天流中预览和操作

📋 任务管理

同一套数据支持 IM 视角和看板视角，子任务从属于父任务

ℹ
本期 Non-Goals：移动端原生 App（P3）、自研 Agent 引擎、完整 CI/CD 流水线、语音/视频通话均不作为 MVP 范围
§2 用户画像

User Personas

👨‍💻 主要：小飞 — 独立全栈开发者

日常用 Claude Code 写后端、Codex 写前端。厌倦在两个终端间反复复制上下文。希望在一个界面上像用微信一样：新建群聊，拉入"前端 Agent"和"后端 Agent"，说一句需求，两个 Agent 各自产出、自动协调。

🧑‍💼 次要：阿豆 — 非技术产品经理

不会写代码但有清晰的产品想法。希望像和设计师沟通一样和 AI Agent 对话，Agent 直接生成可预览的网页，在聊天流中看到效果、提出修改意见，不打开任何代码编辑器。

§3 核心需求

Core User Stories（BDD 格式）

Story 1

单聊模式完成任务

与单个 Agent 进行 1v1 对话并下达编码任务，快速获得代码产出并在聊天流中预览结果。
Given 用户创建与 "Claude Code" Agent 私聊 → When 发送"用 React 写一个计数器组件" → Then Agent 返回代码块 + 网页预览卡片
Story 2

群聊模式多 Agent 协作

在群聊中 @协调者 或直接发送任务，由协调者自动拆解并分配，前后端代码在一个对话中协同产出。
Given 群聊拉入 FrontendAgent + BackendAgent → When 发送"帮我做一个博客系统" → Then 协调者拆解为子任务 → 并行分派 → 产物依次展示
Story 3

产物内联预览与迭代

在聊天流中直接预览 Agent 产出物，无需切换工具完成"需求→预览→修改→确认"闭环。
Given Agent 返回 HTML/CSS/JS → Then 聊天流中渲染网页预览卡片（内联 iframe）
Given 代码修改以 Diff 格式呈现 → Then 渲染 Diff 视图（绿/红标注增删行）
Story 4

对话上下文管理与 Agent 切换

在不同 Agent 之间通过 Harness 自动传递关键上下文，用户无需重复解释项目背景。
Story 5

创建自定义 Agent

通过表单或对话创建自定义 Agent（System Prompt + 模型配置 + 工具集），为特定场景定制 Agent 行为。

§4 功能需求 · B

群组功能（= 频道）

💡
群组 = 频道，Agent 可以同时存在于多个群组中。创建群组时自动生成一个协调者（Coordinator = AI + Harness），群组成员列表可见，不可移除。

协调者工作机制

用户/成员发送消息到群组 │ ▼ 协调者程序接收消息 │ ├─ 用户 @协调者 或 消息包含任务意图（自动检测） │ │ │ ▼ │ 协调者 AI 进行任务分解 │ │ → 分析需求 → 生成子任务列表 → 匹配 Agent 能力 │ │ → 返回结构化 JSON（子任务 + 被分配的 Agent） │ │ │ ▼ │ Harness 校验 → 编译 DAG → 分发执行 │ │ │ ▼ │ Agent 并行/串行执行 → 结果合并 → 回复到群聊 │ └─ 非任务（普通聊天消息 / @指定 Agent） → 不触发任务分解，仅作为对话上下文保留

消息路由规则

操作行为
直接发送（不 @任何人）全体可见；系统自动检测是否有任务意图
@协调者 消息内容显式触发协调者进行任务分解
@AgentName 消息内容仅被 @ 的 Agent 处理，协调者不介入
@All 消息内容群组内所有 Agent 响应（不含协调者）

上下文三层体系

层级范围存储用途
热上下文最近 15-20 条消息Redis（实时）直接注入 LLM prompt
长期上下文被 pin 的消息 + 摘要PostgreSQL跨会话持久化
历史预览更早的对话摘要占位本地文件系统用户可展开查看

§4 功能需求 · C

任务管理

💡
聊天中派发的任务 = 任务界面的任务，同一套数据。

任务模型

父任务 (Task) ├── 子任务 1 (SubTask) → 负责人: FrontendAgent → completed ├── 子任务 2 (SubTask) → 负责人: BackendAgent → running └── 子任务 3 (SubTask) → 负责人: ReviewerAgent → pending (依赖 1,2)

任务属性

属性类型说明
idUUID任务唯一标识
titlestring任务标题
statusenumpending / queued / running / completed / failed / cancelled
priorityenumcritical / high / medium / low
assigneeUUID负责人/负责群组 ID
parent_task_idUUID?父任务 ID
subtasksUUID[]子任务 ID 列表
sourceenumchat（聊天派发）/ manual（手动创建）

§9

风险与边界条件

已知风险

风险影响缓解措施
多 Agent 并发上下文污染任务结果不一致全局-私有双层上下文 + 共享制品只读
LLM token 消耗不可控成本爆炸四道硬闸：步骤/Token/时长/工具调用上限
Agent 输出质量不稳定子任务失败率高Harness 重试 + 失败自动人工介入
WebSocket 不稳定消息丢失PostgreSQL 持久化兜底 + 重连恢复
API Key 泄露安全事件AES-256-GCM 加密 + 前端密码模式

边界条件

群组 Agent 上限：20 个 热上下文：20 条 Agent 并发：3 个 子任务嵌套：1 层 API Key 不可查看明文 Agent name 全局唯一
