## DD-M 洞察（每轮 ≥ 1 条）

1. **[DD-M 洞察-1]** M-C03 在 [DD-001:DD洞察-2] 被识别为"纯函数 in-proc"高风险模块。本框架通过 @pure + @in_process_only 双装饰器固化约束，使 CI grep 检查可强制执行。

2. **[DD-M 洞察-2]** TemplateConfig 选用 frozen=True + extra="forbid" 是 Pydantic v2 "严格不可变 Value Object" 标准做法，需在测试侧添加 frozen_mutation_guard fixture 提醒不可 in-place 修改。

3. **[DD-M 洞察-3]** merger.py 与 schema.py 的依赖方向：merger 依赖 schema 中的类型与异常（合理），但 schema 故意不依赖 merger（避免循环）。这种"类型下沉、实现分离"是 in-proc 纯函数模块的推荐分层。

4. **[DD-M 洞察-4]** 测试覆盖率目标 ≥ 95% 来自 [MD-MCP-V1.0-20260602.md#M-C03]，但 merger.py 的 merge / merge_with_diff 函数体当前为 `raise NotImplementedError` 占位（仅注释，无业务代码）。覆盖率统计将在 DD-S 骨架完成后由实际代码填充。

5. **[DD-M 洞察-5]** validate 函数返回 ValidationResult（结构化对象）而非直接抛异常，给予调用方两种路径：a) 自行判断 valid 字段；b) 调用 raise_if_invalid() 一键抛出。这种"灵活 + 严格"双路径适合框架层调用。
