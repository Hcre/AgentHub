1. **[DD-M洞察-1] leader 锁注入策略** — 5min 周期调度可能跨周期重叠；leader 锁由调用方注入避免与 M-A04 重复实现。FDR-004 已记录。

2. **[DD-M洞察-2] 跨模块依赖通过 IC** — M-C05/M-C06/M-D01/M-EV01 依赖均通过接口契约声明；文件框架不引入实现，避免循环依赖与版本耦合。

3. **[DD-M洞察-3] commit 终态防御** — 防御性抛 NotCompensableError 避免 silent bug。FDR-005 已记录。

4. **[DD-M洞察-4] snapshot 非副作用步骤** — compensate 为 no-op；真正的状态恢复由 snapshot 持久化数据直接用于 apply.revoke + restore。FDR-006 已记录。

5. **[DD-M洞察-5] 测试覆盖盲区** — 现有 15 用例覆盖 4 步 × 主要路径；建议 DD-001 后续追加并发场景（同一 ws 多实例竞争 leader 锁）作为增强测试。

6. **[DD-M洞察-6] 文件膨胀预警** — 当前 7 生产 + 3 测试 = 10 文件，符合 [soul 4.2] 模块复杂度×2~5 范围；若未来增加"灰度迁移"或"回放模式"，需先做文件合并评估。
