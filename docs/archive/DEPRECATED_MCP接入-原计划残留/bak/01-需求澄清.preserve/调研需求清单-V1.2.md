## 二、V1.2 新增 4 条调研项（移交 SA/TD/AR 阶段持续验证）

> 本轮采纳的修订引入新的技术假设，需在下游阶段持续验证。

### R-023 cgroup v2 在 macOS WSL2 / Docker Desktop 内部表现 [P1]
- **指向 PRD 条目**：F-014（V1.2 修订）
- **假设陈述**：Linux 上 cgroup v2 `pids.max=1` + `memory.max=256M` 在 WSL2 / Docker Desktop 容器内表现一致。
- **期望验证问题**：
  1. WSL2 内核版本（5.10+）是否默认启用 cgroup v2？
  2. Docker Desktop on Mac 是否支持 cgroup v2 透传？
  3. 用户场景中 Windows 11 Home 是否能保证 WSL2 安装？
- **调研方式**：实测 WSL2 / Docker Desktop on Mac/Win 三档环境
- **下游**：TD-001 / AR-001 决策容器化与 fallback 策略
- **优先级**：P1

### R-024 sparfenyuk/mcp-proxy 维护活跃度与兼容性 [P1]
- **指向 PRD 条目**：NF-10（V1.2 修订）
- **假设陈述**：sparfenyuk/mcp-proxy（MIT）活跃维护、兼容 MCP 2025-06-18 规范、stdio↔Streamable HTTP/SSE 全双向。
- **期望验证问题**：
  1. 仓库近 90 天提交频率、open issues 数、最近 release？
  2. 是否支持 2025-06-18 规范完整握手？
  3. 与官方 `mcp` PyPI 包（≥1.10）的依赖兼容性？
- **调研方式**：GitHub stats + 实测桥接 3 个内置模板
- **下游**：AR-001 决策是否锁定版本号
- **优先级**：P1

### R-025 PostgreSQL MCP fork（crystaldba/postgres-mcp）成熟度 [P0]
- **指向 PRD 条目**：F-017（V1.2 修订，BLOCKING 替换）
- **假设陈述**：`crystaldba/postgres-mcp` 或同类社区 fork 已修复 CVE-2025-49596 且可用作内置模板。
- **期望验证问题**：
  1. fork 是否真实包含 CVE 修复 patch？patch ID 与 commit hash？
  2. 维护团队、license、近 30 天 commit 活跃度？
  3. 是否有 v8.0.0+ 修复版 PostgreSQL MCP Server（非该 fork）作为备选？
  4. dry-run CVE 回归测试用例（注入 SQL）是否被 fork 拒绝？
- **调研方式**：GitHub + Datadog CVE 报告 + 实测注入测试
- **下游**：AR-001 / DD-001 决策最终模板源
- **优先级**：P0（必须在发布前确认）

### R-026 yarl.URL DNS 固定实现方式 [P1]
- **指向 PRD 条目**：F-016（V1.2 修订）
- **假设陈述**：`yarl.URL` + 自定义 DNS resolver 可实现首次解析锁定 + 重定向校验。
- **期望验证问题**：
  1. yarl 是否原生提供 DNS 固定，还是需 httpx custom transport / aiodns 配合？
  2. 60s TTL 是否合理？业界 SSRF defense 建议值？
  3. 性能开销（每次 URL 拼接的 DNS 查询缓存命中率）？
- **调研方式**：yarl/httpx/aiodns 官方文档 + OWASP SSRF Cheat Sheet 最新版
- **下游**：DD-001 实现细节决策
- **优先级**：P1
