### P0 优先级（核心路径，必须验证）

#### R-001 MCP 2025-06-18 规范 Streamable HTTP 传输细节 [P0]
- **指向 PRD 条目**：F-016
- **假设陈述**：MCP 2025-06-18 规范已正式弃用「HTTP+SSE 双通道」传输，统一为 Streamable HTTP（单端点 POST + 可选 SSE 响应），握手/能力协商协议变更。
- **期望验证问题**：
  1. 2025-06-18 规范文本中关于传输的章节是否明确弃用旧 HTTP+SSE？
  2. Streamable HTTP 的请求/响应 schema（InitializeRequest / ToolsListRequest / ToolCallRequest / JSON-RPC 2.0 包装）是什么？
  3. 是否有官方 Python SDK (`mcp` PyPI) 支持？最低版本号？
  4. mcp-proxy 转译层是否存在开源实现？GitHub 仓库地址、star 数、license？
- **调研方式**：官方规范 + GitHub 仓库 + PyPI `mcp` 包
- **优先级**：P0

#### R-002 三个 Runtime 的 `--mcp-config` 兼容性 [P0]
- **指向 PRD 条目**：F-012
- **假设陈述**：ClaudeCode / OpenCode / PiAgent 三个 Runtime 均支持 CLI 参数 `--mcp-config <path>` 注入 MCP server 配置。
- **期望验证问题**：
  1. 三个 Runtime 实际文件中 `--mcp-config` 参数名是否完全一致？
  2. 配置文件 schema（JSON 字段）是否一致？stdio command+args 字段、Streamable HTTP url 字段、auth headers 字段命名？
  3. 启动时是否立即拉 manifest 校验，还是延迟到第一次工具调用？
  4. 热重载机制（修改 bindings 后 Runtime 是否需要重启）？
- **调研方式**：`src/backend/app/infrastructure/llm/` 三个 Runtime 文件 + 官方文档
- **优先级**：P0

#### R-003 stdio MCP 沙箱跨平台实现 [P0]
- **指向 PRD 条目**：F-014
- **假设陈述**：Windows 上 Docker 优先，Linux/macOS 上 setrlimit 足够。
- **期望验证问题**：
  1. Windows 11 Home 是否预装 Docker Desktop / WSL2？用户场景是否覆盖？
  2. Windows Job Objects 在 Python `pywin32` 中的 API 调用复杂度？是否需要 C 扩展？
  3. Linux `resource.setrlimit(RLIMIT_NPROC, (1, 1))` 是否会同时限制父进程？需不需要 `prctl(PR_SET_PDEATHSIG)`？
  4. macOS 上 `setrlimit` 是否等价于 Linux？是否有 `sandbox-exec` 替代方案？
- **调研方式**：Python 官方文档 + pywin32 文档 + macOS `sandbox-exec` 文档
- **优先级**：P0

#### R-004 进程池自建 vs 引入 mcp-proxy 决策 [P0]
- **指向 PRD 条目**：NF-10
- **假设陈述**：AgentHub 倾向自建进程池（轻量、零外部依赖、符合 5 层洋葱）。
- **期望验证问题**：
  1. mcp-proxy（`smartcomputerlab/mcp-proxy` 或类似仓库）的架构设计：异步池？LRU？闲置回收？
  2. mcp-proxy 的依赖图（Python 包依赖）？是否引入重型框架（如 FastAPI、asyncio 集群）？
  3. mcp-proxy 是否有 license 限制（MIT / Apache 2.0）？
  4. AgentHub L1 Infrastructure 层是否已有进程池抽象（asyncio subprocess）？自建是否完全内部消化？
  5. mcp-proxy 是否支持「HTTP+SSE → Streamable HTTP」转译？
- **调研方式**：mcp-proxy GitHub + npm/PyPI + 依赖分析
- **优先级**：P0

#### R-005 闲置超时回收精度 [P0]
- **指向 PRD 条目**：F-007
- **假设陈述**：5min 闲置 + 30s 扫描周期，回收准确率 ≥ 90%。
- **期望验证问题**：
  1. asyncio 任务调度最小粒度？5min 定时器在 1000 并发进程下延迟？
  2. 是否需要「事件触发 + 兜底扫描」双保险？业界实践？
  3. 冷启动 P95 ≤ 1.2s 目标在 Windows / Linux / macOS 三平台均可达？
- **调研方式**：asyncio 文档 + 竞品（Anthropic SDK、Mistral MCP 客户端）实现
- **优先级**：P0

#### R-006 WebSocket 工具事件 schema [P0]
- **指向 PRD 条目**：F-013
- **假设陈述**：`tool_call` / `tool_result` 事件 schema 简单 JSON，200ms 内可达 UI。

  2. 三个 Runtime 上报 `tool_call` / `tool_result` 的延迟（从 Runtime 触发到 WebSocket 推送）实际值？
  3. 截断 200 字符 args_preview / 500 字符 result_preview 是否够用？业界 MCP 客户端实践？
- **调研方式**：AgentHub 现有 WebSocket 实现 + Runtime 源码
- **优先级**：P0

#### R-007 Inbox 审批流与现有 IM 集成 [P0]
