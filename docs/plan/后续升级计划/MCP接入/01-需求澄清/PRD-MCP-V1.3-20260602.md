## 1. 需求背景与目标

### 1.1 背景 [上游编号:UR-001]

AgentHub 是一个 IM 聊天式多 Agent 协作平台，采用 5 层洋葱架构（L1 Infrastructure → L2 Domain → L3 Application → L4 API → L5 Presentation），技术栈为 FastAPI + React/TS + PostgreSQL + Redis + Docker，提供 CLI/SDK 双轨 Adapter。已实现 3 个 Runtime（ClaudeCode / OpenCode / PiAgent），Codex / Trae 规划中。

当前瓶颈 [PM推断:依据 — 需求中提到"为 Agent 接入 MCP"隐含工具扩展能力受限]:
- Agent 工具能力受限于 Runtime 自身实现，扩展需逐 Runtime 适配
- 缺乏统一的工具/资源/提示词协议标准
- 工具共享与复用困难

MCP（Model Context Protocol, Anthropic 2024-11 开源，2025-06-18 最新规范）提供标准化的工具（tools）/资源（resources）/提示词（prompts）协议，是行业事实标准 [PM推断:依据 — 2024-11 Anthropic 开源后被广泛采纳]。

### 1.2 核心目标

| 目标编号 | 目标描述 | 优先级 |
|---|---|---|
| G-01 | 用户可在 AgentHub 内浏览/搜索/安装 MCP，扩展 Agent 能力 | P0 |
| G-02 | 用户可将 MCP 绑定到 Agent，通过 CLI Adapter 注入并通过 WebSocket 接收工具调用事件 | P0 |
| G-03 | 用户可创建自定义 MCP（stdio/sse/http），通过 dry-run 沙箱验证，并使用模板库 | P0 |
| G-04 | 保证 MCP 接入的可观测性、可审计性与安全隔离 | P1 |

### 1.3 成功指标

| 指标编号 | 指标 | 目标值 | 测量方式 |
|---|---|---|---|
| S-01 | MCP 详情页 LCP (Largest Contentful Paint) | ≤ 1.5s（P95） | 前端性能监控 |
| S-02 | 工具调用端到端延迟 | ≤ 800ms（P95，stdio 本地） | 链路追踪 |
| S-03 | dry-run 沙箱验证误报率 | ≤ 2% | 沙箱日志回放对比 |
| S-04 | 上线 30 天内市场上线 MCP 数 | ≥ 20 个（其中官方 ≥ 5 个） | 平台计数 |
| S-05 | 工具调用事件 WebSocket 投递成功率 | ≥ 99.5% | WebSocket 心跳与回执 |
| S-06 | MCP 安装失败率 | ≤ 1%（不含网络异常） | 安装日志 |
| S-07 | MCP 配置 schema 校验覆盖率 | 100%（所有创建/安装必经） | 单元/集成测试 |

## 3. 功能需求清单

> 数量：30 项（PRD 硬性约束 ≤ 30）
> 优先级分布：P0=9(30%) / P1=9(30%) / P2=7(23%) / P3=5(17%) — 符合 P0 ≤ 30% 约束

### 3.1 P0 — 核心必须

#### F-001 MCP 市场首页
- 描述：提供 MCP 市场的着陆页，包含推荐位、最新上架、热门分类入口。集成于 AgentHub L5 Presentation 层，路由 `/mcp-market`。
- 优先级：P0
- 用户角色：R-01, R-03
- 验收标准：① 当 R-03 访问 `/mcp-market` 时，页面 P95 LCP ≤ 1.5s；② 首页展示至少 6 个推荐位卡片与最新 10 个 MCP 列表；③ 当 R-01 配置"推荐位"后，10 秒内生效。
- 依赖功能：F-002, F-003
- 冲突边界：与"不做"清单 B-01 不冲突

#### F-002 MCP 列表/搜索/筛选
- 描述：列表支持分页（每页 20 条）、关键字搜索（命中 name/description/tags）、按分类/传输类型/评分/安装量筛选。
- 优先级：P0
- 用户角色：R-03
- 验收标准：① 在 10000 条 MCP 库下，搜索 P95 响应 ≤ 300ms（PostgreSQL 全文索引 + Redis 缓存）；② 筛选条件以 URL query 形式可分享；③ 列表项展示名称、版本、传输类型、安装量、评分。
- 依赖功能：F-001
- 冲突边界：与 B-02 不冲突

#### F-003 MCP 详情页
- 描述：展示 MCP 完整元数据（name/description/version/author/transport/schema/samples），含 README、版本历史、安装按钮。
- 优先级：P0
- 用户角色：R-03, R-01
- 验收标准：① 详情页 P95 LCP ≤ 1.5s；② 当 MCP 描述 ≥ 5000 字时仍可在 1s 内首屏；③ 详情页"安装"按钮对未登录用户禁用并提示登录。
- 依赖功能：F-001, F-002
- 冲突边界：与 B-03 不冲突

#### F-004 一键安装 MCP
- 描述：R-03 在详情页点击"安装"，平台为该用户创建 MCP 实例（生成 instance_id，写入 user_mcp_installations 表），返回安装结果。
- 优先级：P0
- 用户角色：R-03
- 验收标准：① 安装成功后 5 秒内 instance 进入 `ready` 状态；② 安装失败时返回明确错误码（网络/依赖/权限）；③ 安装幂等：同一 user + 同一 mcp_version 重复安装返回同一 instance。
- 依赖功能：F-003, F-024
- 冲突边界：与 B-04 不冲突

#### F-009 Agent 绑定 MCP
- 描述：在 Agent 配置页选择已安装的 MCP instance 与该 MCP 暴露的 tools 子集（默认全选），形成绑定关系（agent_mcp_bindings）。
- 优先级：P0
- 用户角色：R-03
- 验收标准：① 绑定成功后，Agent 启动时 CLI Adapter 注入 MCP 配置（见 F-012）；② 绑定后用户可立即在 IM 会话中调用该 MCP 工具；③ 解绑后该 Agent 不再注入该 MCP。
- 依赖功能：F-004, F-012
- 冲突边界：与 B-05 不冲突

#### F-012 CLI Adapter 注入
- 描述：当 Agent 启动时，CLI Adapter（适配 ClaudeCode/OpenCode/PiAgent 三种 Runtime）将已绑定的 MCP 配置以标准 MCP 协议格式注入 Runtime 进程（stdio）或转发到指定 sse/http 端点。
- 优先级：P0
- 用户角色：R-03
- 验收标准：① 注入内容遵循 MCP 2025-06-18 规范 `initialize`/`tools/list` 协议；② 注入过程不阻塞 Agent 启动超过 1s；③ 注入失败时 Agent 仍可启动但记录 warning 日志。
- 依赖功能：F-009
- 冲突边界：与 B-06 不冲突

#### F-014 WebSocket 工具调用事件
- 描述：Runtime 通过 WebSocket 向 AgentHub 上报 `tool_call_request` / `tool_call_response` / `tool_call_progress` / `tool_call_error` 事件，平台按 agent_id + call_id 路由。
- 优先级：P0
- 用户角色：R-03, R-04
- 验收标准：① WebSocket 端到端投递成功率 ≥ 99.5%（S-05）；② 单个 Agent 并发 50 个 tool_call 时不丢消息；③ 断线 30s 内自动重连并重发未 ack 事件。
- 依赖功能：F-012
- 冲突边界：与 B-07 不冲突

#### F-018 创建 MCP - stdio 传输
- 描述：R-02 通过表单/JSON/YAML 创建一个 stdio 传输的 MCP，平台为该 MCP 生成独立配置条目。
- 优先级：P0
- 用户角色：R-02
- 验收标准：① 提交后 5 秒内返回 mcp_id；② 配置必须通过 schema 校验（F-024）；③ 自动触发 dry-run（F-021），失败则拒绝入库。
- 依赖功能：F-021, F-024
- 冲突边界：与 B-08 不冲突

#### F-021 创建 MCP - dry-run 沙箱验证
- 描述：在 MCP 首次入库前，平台启动隔离容器（Docker）执行 MCP `initialize` + `tools/list`，验证协议合规性、超时、资源占用。失败时返回错误码与日志。
- 优先级：P0
- 用户角色：R-02
- 验收标准：① 单次 dry-run 超时硬上限 30s（可配置）；② 沙箱 CPU ≤ 1 核、内存 ≤ 512MB、网络默认隔离；③ dry-run 日志保留 7 天，R-02 可下载；④ 误报率 ≤ 2%（S-03）。
- 依赖功能：F-024
- 冲突边界：与 B-09 不冲突

### 3.2 P1 — 重要必需

#### F-005 卸载 MCP
- 描述：R-03 卸载已安装的 MCP instance；级联检查是否有 Agent 绑定，有则提示先解绑。
- 优先级：P1
- 用户角色：R-03
- 验收标准：① 卸载前展示绑定 Agent 数量；② 有绑定时需二次确认；③ 卸载后该 instance 在 60s 内从所有 Agent 注入配置中移除。
- 依赖功能：F-009
- 冲突边界：与 B-04 不冲突

#### F-008 MCP 版本管理
- 描述：MCP 同一 name 可存在多版本，详情页可切换版本；安装时可指定 version 或 `latest`。
- 优先级：P1
- 用户角色：R-02, R-03
- 验收标准：① 同一 mcp_name 最多保留 50 个历史版本；② 版本号遵循 semver；③ 升级不破坏向后兼容调用。
- 依赖功能：F-003
- 冲突边界：与 B-10 不冲突

#### F-010 Agent 解除 MCP 绑定
- 描述：R-03 在 Agent 配置页解除绑定；解除后该 Agent 不再接收该 MCP 工具调用。
- 优先级：P1
- 用户角色：R-03
- 验收标准：① 解绑 5 秒内 WebSocket 路由表更新；② 解绑后正在执行的 tool_call 不中断，但后续路由阻断。
- 依赖功能：F-009
- 冲突边界：与 B-05 不冲突

#### F-013 SDK Adapter 注入
- 描述：提供 Python/Node SDK 形式的 Adapter（与 CLI Adapter 并列），R-03 嵌入自有代码即可使用。
- 优先级：P1
- 用户角色：R-03
- 验收标准：① SDK 版本与平台版本解耦，向后兼容最近 3 个平台版本；② SDK 调用失败抛出标准化异常（含 error_code）。
- 依赖功能：F-012
- 冲突边界：与 B-06 不冲突

#### F-016 工具调用超时/取消
- 描述：单次 tool_call 默认 30s 超时；R-03 可在 IM 会话中显式取消正在执行的 call。
- 优先级：P1
- 用户角色：R-03
- 验收标准：① 超时返回 error_code=`TIMEOUT`；② 取消请求 2s 内到达 Runtime；③ 取消时沙箱进程被 SIGTERM。
- 依赖功能：F-014
- 冲突边界：与 B-11 不冲突

#### F-017 工具调用审计日志
- 描述：所有 tool_call 写入审计表（含 caller/binding_id/mcp_id/tool_name/args_hash/result_code/duration），R-04 可查询与导出。
- 优先级：P1
- 用户角色：R-04, R-01
- 验收标准：① 日志写入 P95 ≤ 50ms（异步落盘）；② 单租户可查询 90 天历史；③ 导出格式 CSV/JSONL 任选。
- 依赖功能：F-014
- 冲突边界：与 B-12 不冲突

#### F-019 创建 MCP - sse/http 传输
- 描述：支持 SSE 与 streamable-HTTP 两种传输的 MCP 创建。URL 由 R-02 提交，平台 ping 验证可达性。
- 优先级：P1
- 用户角色：R-02
- 验收标准：① 平台对 sse/http 端点执行 3 次 ping（P95 ≤ 1s）；② 失败返回错误码与可达性证据。
- 依赖功能：F-018, F-021, F-024
- 冲突边界：与 B-08 不冲突

#### F-022 MCP 模板库
- 描述：预置 5 个官方模板（filesystem / fetch / git / sqlite / shell），R-02 可"基于模板创建"以减少配置成本。
- 优先级：P1
- 用户角色：R-02
- 验收标准：① 模板列表首次加载 ≤ 200ms；② 模板填充后字段与 schema 一致性 100%。
- 依赖功能：F-018
- 冲突边界：与 B-13 不冲突

#### F-025 MCP 权限/安全策略
- 描述：MCP 可声明所需权限（filesystem 范围、network egress、env 变量），平台在安装时展示并由 R-03 显式同意。
- 优先级：P1
- 用户角色：R-03, R-01
- 验收标准：① 未授权权限触发时返回 error_code=`PERMISSION_DENIED`；② 权限变更需 R-03 再次同意。
- 依赖功能：F-018, F-021
- 冲突边界：与 B-09 不冲突

#### F-027 MCP 错误处理与降级
- 描述：MCP 实例不可用时，工具调用按"重试 1 次 → 失败回退 → 提示 R-03"三段式处理。
- 优先级：P1
- 用户角色：R-03
- 验收标准：① 单次重试间隔 2s；② 失败回退返回友好提示与建议（如"检查 MCP 是否在线"）。
- 依赖功能：F-014
- 冲突边界：与 B-11 不冲突

### 3.3 P2 — 期望增强

#### F-007 MCP 分类/标签
- 描述：MCP 可被分类（filesystem / network / database / dev-tools / other）与打标签。
- 优先级：P2
- 用户角色：R-01, R-02
- 验收标准：① 分类最多 2 级；② 标签无层级且每个 MCP 最多 10 个。

#### F-011 批量绑定/导入 MCP
- 描述：R-03 上传 JSON/YAML 批量导入 MCP 配置并一次性绑定到指定 Agent。
- 优先级：P2
- 用户角色：R-03
- 验收标准：① 单次批量最多 50 个；② 失败条目独立标记，不阻塞其他条目。
- 依赖功能：F-009, F-018

#### F-020 模板填充/复制
- 描述：R-02 在模板基础上填充参数后另存为新 MCP；同时支持复制已有 MCP 作为起点。
- 优先级：P2
- 用户角色：R-02
- 验收标准：① 复制后新 MCP 的 mcp_id 全局唯一；② 复制时显式标注"来源 MCP"。
- 依赖功能：F-022

#### F-023 MCP 配置文件 schema 校验
- 描述：所有 MCP 入库前通过 JSON Schema 校验，错误信息含字段路径。
- 优先级：P2
- 用户角色：R-02
- 验收标准：① 校验错误含精确字段路径（如 `tools[2].inputSchema.required[0]`）；② schema 版本与 MCP 协议版本绑定。
- 依赖功能：F-018

#### F-026 MCP 私有/公开开关
- 描述：MCP 默认为私有（仅创建者可见），可切换为公开（出现在市场中）。
- 优先级：P2
- 用户角色：R-02
- 验收标准：① 公开需 R-01 审核通过（后台开关，MVP 可省略审核但保留字段）；② 私有→公开后 30s 内出现在市场搜索。
- 依赖功能：F-001, F-002

#### F-028 MCP 使用量统计
- 描述：MCP 实例维度统计调用次数、成功率、平均延迟；详情页"数据"tab 展示。
- 优先级：P2
- 用户角色：R-02, R-03
- 验收标准：① 统计粒度 1h/24h/7d 可切换；② 数据延迟 ≤ 5min。

#### F-030 MCP 监控告警
- 描述：MCP 错误率超阈值（默认 5min 内 > 30%）触发告警，平台向 R-02 发送站内信。
- 优先级：P2
- 用户角色：R-02, R-01
- 验收标准：① 告警延迟 ≤ 1min；② 告警阈值 R-01 可配置。

### 3.4 P3 — 锦上添花

#### F-006 MCP 评分/评论
- 描述：R-03 可对已安装 MCP 评分（1-5 星）与评论；R-02 可回复。
- 优先级：P3
- 用户角色：R-03, R-02
- 验收标准：① 每用户对同一 MCP 只能评分一次（可修改）；② 评论最多 500 字。

#### F-029 MCP 多语言/国际化
- 描述：MCP 详情与市场文案支持中/英双语切换。
- 优先级：P3
- 用户角色：R-03
- 验收标准：① 默认语言跟随浏览器；② 切换无刷新。

#### F-031 MCP 收藏夹
- 描述：R-03 可收藏 MCP 至"我的收藏"。
- 优先级：P3
- 用户角色：R-03
- 验收标准：① 收藏列表 P95 加载 ≤ 200ms；② 收藏上限 200 个。

#### F-032 MCP 分享/导出配置
- 描述：R-03 可导出已安装 MCP 的配置 JSON，分享给他人导入。
- 优先级：P3
- 用户角色：R-03
- 验收标准：① 导出文件含版本与来源标识；② 导入时做 schema 校验。

#### F-033 MCP 更新通知
- 描述：MCP 新版本发布时，已安装用户收到站内信通知。
- 优先级：P3
- 用户角色：R-03
- 验收标准：① 通知延迟 ≤ 5min；② 通知可关闭（per-MCP）。
