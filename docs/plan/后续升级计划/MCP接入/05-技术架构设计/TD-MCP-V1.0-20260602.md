## TD-001 mcp-proxy 6 项已知缺陷

```
[债务编号] TD-001
[债务描述] sparfenyuk/mcp-proxy 0.5.x 存在 6 项已知缺陷（首次调用失败 / keepalive 缺失 / TTL 清理缺失 / serverInfo 包装问题 / wrapped stdio 边界 / 端点文档不全）
[影响模块]
  M-A01 (API Gateway) - 6 项 workaround 在 mcp-tool_first_call 层
  M-B02 (Process Pool) - 进程启动时应用 keepalive + TTL
  M-B05 (MCP Create) - 端点文档生成
[风险等级] 中度
[产生原因]
  - 调研发现 mcp-proxy 0.5.x 是 V1.0 唯一可用 stdio↔Streamable HTTP 双向桥接实现
  - 上游项目活跃但功能尚未稳定
  - V1.0 时间窗口不足以 fork + 修复 6 项缺陷
[偿还计划]
  - V1.0.1 (2026 Q3): fork sparfenyuk/mcp-proxy 到内部仓库 agenthub/mcp-proxy
  - V1.0.2 (2026 Q3): 修复 6 项缺陷, 提交 PR 上游
  - V1.1 (2026 Q4): 切换到 agenthub/mcp-proxy, 移除 6 项 workaround
  - 验收: mcp_tool_first_call_error_rate < 0.1%, keepalive 60s 持续保活
[接受理由]
  - mcp-proxy 0.5.x 满足 90% 功能需求, 6 项缺陷均有 workaround
  - 自研桥接层 6 个月工作量, ROI 低
  - 6 项 workaround 在代码层隔离, 不影响业务模块
[来源标注] [调研:RSK-10 mcp_proxy 6 项缺陷 + 调研:S-027 推荐自建 Runtime + 引入 mcp-proxy]
```

## TD-002 32 工具全量加载上下文爆炸

```
[债务编号] TD-002
[债务描述] Claude Code 工具搜索功能遇到 > 64 字符工具名会整个 MCP 服务器集成失败；32 工具全量加载时约 134K tokens 接近 Claude Code 上下文上限
[影响模块]
  M-B03 (Binding Engine) - 32 工具上限硬限 (BR-006)
  M-B05 (MCP Create) - 工具搜索延迟
[风险等级] 轻度
[产生原因]
  - V1.0 阶段工具全量加载是 MCP 规范默认行为
  - 工具元数据加载是 Agent 调用前提, V1.0 简化实现
  - 32 工具上限是 Claude Code 实际可用边界
[偿还计划]
  - V2.1 (2026 Q4): 引入 M-B06 工具元数据缓存 (metadata-only, schema 按需)
  - V2.1: 引入 M-D04 Schema-CDN (工具 schema 分布式缓存)
  - 验收: 工具搜索 P95 < 200ms, 单 ws 工具数 64+
[接受理由]
  - V1.0 业务规模 (单 ws < 10 工具) 远未触及 32 上限
  - 8-24 工具区间无明显性能问题
  - V2.1 蓝绿切换风险可控
[来源标注] [SA:CE-007 + ER-V2.1 + 调研:A-02 MCPCrawler]
```

## TD-003 WSL2 cgroup 控制器不全

```
[债务编号] TD-003
[债务描述] WSL2 默认不启用 cgroup v2 完整控制器 (pids.max / memory.max), 仅 systemd 启用后才可用
[影响模块]
  M-C01 (Sandbox Engine) - 沙箱在 WSL2 失效
[风险等级] 轻度
[产生原因]
  - WSL2 微软设计选择, 默认不启用 systemd
  - 修复需 .wslconfig 手动配置 (用户体验门槛)
  - V1.0 业务场景以 Linux/macOS/Windows 原生为主
[偿还计划]
  - V1.0.1: .wslconfig 前置文档 + 启动检查脚本
  - V1.1: setrlimit 降级路径 (CPU/内存限制, 失去 pids 隔离)
  - V2.0: Windows Docker Desktop WSL2 backend 统一方案
  - 验收: WSL2 用户沙箱 P95 < 30s (降级模式)
[接受理由]
  - WSL2 用户比例 < 5% (基于 AgentHub 用户调研)
  - 沙箱非核心功能, V1.0 可降级为 setrlimit
  - 降级路径在 BP-011 步骤 2 已有, 无额外开发
[来源标注] [调研:RSK-09 + R-003 WSL2 cgroup 限制 + S-025 修订建议]
```
