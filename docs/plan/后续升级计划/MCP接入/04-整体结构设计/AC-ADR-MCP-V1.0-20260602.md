# 第一部分：方案对比报告（AC）

> 主方案 vs 备选方案，按 7 项对比维度评估（4.11）

## 主方案：混合架构（分层 + 微服务 + 事件驱动 + 插件化）

- **核心特征**：
  - L5-L4-L2-L1 四层骨架（PRD 已分层）
  - 7 大主题按微服务边界拆分独立部署
  - 跨主题协同走 M-021 事件总线（去重 + ack + 限流）
  - Adapter 与沙箱后端走 M-007/M-013 SPI 插件化
  - M-022 分布式锁保护安装/绑定并发
- **22 个模块 / 30 个功能 = 0.73**
- **优势**：扩展性强、并发反例可解、长期演进成本低
- **风险**：实现复杂度中等、需要事件总线 + 锁服务基础设施

## 备选方案：纯分层单体架构

- **核心特征**：
  - L5-L4-L2-L1 四层骨架
  - 模块间通过函数调用 + 共享数据库表协同
  - 无独立事件总线，依赖数据库事务保证一致性
  - Adapter / 沙箱后端在 M-007/M-013 内部 if-else 分支处理
  - 数据库唯一约束作并发兜底
- **15 个模块 / 30 个功能 = 0.50**
- **优势**：实现简单、部署单体易于运维、学习成本低
- **风险**：CE-001/004/005/011/013/014 等 7 条并发反例难以彻底解决；无法支撑 V2.0 高并发；多 Runtime 接入需修改核心代码

## 7 维度对比评分（权重见 soul 4.11）

| 对比维度 | 权重 | 主方案得分 | 备选方案得分 | 主方案加权 | 备选方案加权 | 评分理由 |
|---|---|---|---|---|---|---|
| 模块内聚度 | 0.15 | 9 | 6 | 1.35 | 0.90 | 主方案 22 模块全部 6/6 通过；备选方案模块过粗（5 个超 10 功能），单一职责弱 |
| 模块间耦合度 | 0.15 | 9 | 5 | 1.35 | 0.75 | 主方案加权耦合 0.28；备选共享数据库表 + 函数直调，耦合度 ≈ 0.6 |
| 可扩展性 | 0.15 | 9 | 4 | 1.35 | 0.60 | 主方案 SPI 插件化 + 事件订阅，新增 Runtime 仅扩展插件；备选需修改核心 |
| 架构简洁度 | 0.15 | 8 | 7 | 1.20 | 1.05 | 主方案 22 模块（0.73）适中；备选 15 模块（0.50）较精简但单模块臃肿 |
| 性能瓶颈风险 | 0.10 | 9 | 5 | 0.90 | 0.50 | 主方案可水平扩展；备选 50 并发 tool_call 易引发数据库行锁竞争 |
| 实现复杂度 | 0.15 | 6 | 9 | 0.90 | 1.35 | 主方案需引入 NATS + Redis Redlock；备选直接函数调用 |
| 成本估算 | 0.15 | 6 | 9 | 0.90 | 1.35 | 主方案：8 人月开发 + 中等云资源；备选：4 人月 + 单体资源 |
| **加权总分** | 1.00 | **8.05** | **5.40** | **8.05** | **6.50** | **主方案 - 备选 = 1.55 ≥ 1.0** |

**选择理由（差值 1.55 → 主方案优势显著）**：

1. **可解决 7 条并发反例** [CE-001/004/005/011/013/014/CE-007] — 备选方案的数据库唯一约束无法防止 race condition 日志噪音
2. **多 Runtime 接入零核心改动** — 备选方案每接一个 Runtime 需修改 M-007 主代码
3. **V2.0 演进顺畅** — 50→1000 并发的 WS 网关分片在备选方案下需重写
4. **审计去重 + 告警去重的清晰边界** — 备选方案需在多处散落去重逻辑
5. **可接受实现复杂度增量** — 8 人月 vs 4 人月，但避免 2027 年重构 20 人月

**成本估算细节：**

| 成本项 | 主方案 | 备选方案 |
|---|---|---|
| 开发人力 | 8 人月（含事件总线 + 锁服务 + 22 模块） | 4 人月（15 模块单体） |
| 基础设施 | NATS×3 + Redis Sentinel×3 + K8s 集群（约 3000 元/月） | 单体服务器 + Redis（约 1500 元/月） |
| 运维成本 | 0.5 人月/月（多服务监控） | 0.2 人月/月 |
| 学习成本 | 2 人周（NATS / Redlock） | 0.5 人周 |

**最终决策：采纳主方案**

# 第二部分：架构决策记录（ADR）

> 9 条 ADR，覆盖所有重大架构决策（R23 满足）

## ADR-001 [架构模式选定为混合架构]
- **状态**：已接受
- **决策内容**：采用「L5-L4-L2-L1 分层骨架 + 7 主题微服务边界 + 事件总线协同 + Adapter/Sandbox 插件化」混合架构
- **决策理由**：见方案对比报告 — 加权总分 8.05 vs 5.40；可解 7 条并发反例；多 Runtime 零核心改动
- **拒绝的替代方案**：纯分层单体架构（成本低但并发反例难解、V2.0 演进重写代价 20 人月）
- **影响范围**：全部 22 个模块、4 视图、演进路线 V1.1/V2.0
- **相关 ADR**：ADR-002, ADR-003, ADR-004, ADR-005
- **来源**：[SA:BP/EX/CE 全面分析]

## ADR-002 [引入 M-021 事件总线作为 L2 协同骨干]
- **状态**：已接受
- **决策内容**：在 L2 业务层之下引入独立的事件总线 M-021（NATS JetStream），所有跨主题协同（binding 变更/installation ready/tool_call event/alert triggered 等 8 个 Topic）通过事件总线异步路由 + ack + 去重
- **决策理由**：①CE-005 50 并发 ack 重发风暴需限流 ②CE-013 ack 重发审计重复需去重 ③事件驱动模式约束 R22 要求跨模块禁止直接调用 ④V2.0 WS 网关分片需事件总线统一路由
- **拒绝的替代方案**：①数据库 outbox 表（一致性好但延迟高 + 数据库压力）②Kafka（功能更强但运维成本高，2026 时点 NATS JetStream 已稳定）③Redis Streams（适合中小规模但持久化能力弱）
- **影响范围**：M-002/005/006/007/008/009/010/014/017/020 共 10 模块
- **相关 ADR**：ADR-005
- **来源**：[TD推断:依据 — CE-005/013 + 事件驱动模式]

## ADR-003 [引入 M-022 分布式锁服务（Redlock）]
- **状态**：已接受
- **决策内容**：M-002 安装、M-006 绑定、M-005 卸载共享 `instance_id` / `user_id+mcp_id` 维度的 Redis Redlock 锁，TTL 5s 自动释放
- **决策理由**：①CE-001 并发安装产生双实例 ②CE-014 卸载与绑定竞态 ③数据库唯一约束仅作兜底，无法防止 race condition 日志噪音
- **拒绝的替代方案**：①PostgreSQL `SELECT FOR UPDATE`（DB 行锁压力大，长事务风险）②ZooKeeper（运维成本高，AgentHub 平台已用 Redis）
- **影响范围**：M-002/005/006，新增 IF-041/042
- **相关 ADR**：ADR-001
- **来源**：[TD推断:依据 — CE-001/014 修复]

## ADR-004 [Adapter 与 Sandbox 采用 SPI 插件化]
- **状态**：已接受
- **决策内容**：M-007 暴露 `AdapterPlugin{translate, inject, healthCheck}` SPI；M-013 暴露 `SandboxBackend{start, limitResources, enforceNetwork, teardown}` SPI；ClaudeCode/OpenCode/PiAgent/Docker/cgroup_v2/setrlimit/gVisor/Kata 等均通过 SPI 实现，独立打包
- **决策理由**：①CR-001 PRD 已澄清「L4 翻译层」职责 ②V1.3 沙箱后端切换需零核心改动 ③扩展点验收 4.14 通过率 100%
- **拒绝的替代方案**：①if-else 分支（每加一种 Runtime 改核心代码，违反 OCP）②反射（复杂度高，调试困难）
- **影响范围**：M-007/M-013，演进路线 V1.3
- **相关 ADR**：ADR-001, ADR-006
- **来源**：[SA:CR-001 + 调研报告 S-056] + [TD推断:CE-006 修复]

## ADR-005 [审计日志强制 INSERT ONLY + event_id 去重]
- **状态**：已接受
- **决策内容**：DE-009 审计日志数据库权限层 `REVOKE UPDATE/DELETE`；M-010 写入前 SELECT event_id 已存在则跳过；90 天热存后 S3 归档
- **决策理由**：①BR R-018 不可变审计 ②NF-07 完整性 ③CE-013 ack 重发导致重复
- **拒绝的替代方案**：①应用层不可变控制（DBA 可绕过）②区块链（成本不匹配）
- **影响范围**：M-010、DE-009
- **相关 ADR**：ADR-002
- **来源**：[SA:R-018, CE-013, NF-07]

## ADR-006 [沙箱后端不可用强制阻断 dry-run]
- **状态**：已接受
- **决策内容**：M-013 启动时检测 SandboxBackend SPI 可用性；后端全部不可用时（如 Windows Home 缺 WSL2 + 无 Docker），R-01 强制阻断 dry-run，提示升级环境，禁止 MCP 入库
- **决策理由**：①CE-006 静默降级导致危险 MCP 入库 ②R-01 安全责任明确（NF-04）
- **拒绝的替代方案**：①setrlimit 降级警告（已被调研报告 S-049 标记 ⚠️）②跳过 dry-run（违反 PRD F-021 强制要求）
- **影响范围**：M-013，部署视图（Windows 部署降级方案）
- **相关 ADR**：ADR-004
- **来源**：[TD推断:CE-006 修复]

## ADR-007 [LRU 清理跳过 is_pinned OR is_critical_patch]
- **状态**：已接受
- **决策内容**：M-005 版本 LRU 清理条件改为 `is_pinned=false AND is_critical_patch=false`
- **决策理由**：①CE-002 CVE 紧急 patch 被误清理 ②BR R-003/R-004 冲突仲裁
- **拒绝的替代方案**：①扩容上限至 100（治标不治本，2026-06 时点已有 MCP 50 版本接近上限）
- **影响范围**：M-005、DE-003 新增 is_critical_patch 字段
- **相关 ADR**：ADR-001
- **来源**：[SA:CE-002 + BR R-003/R-004 仲裁]

## ADR-008 [WS 网关令牌桶限流 100 req/s]
- **状态**：已接受
- **决策内容**：M-008 ack 重发加令牌桶限流 100 req/s，超限排队 + 触发告警
- **决策理由**：①CE-005 50 并发 ack 重发风暴 ②NF-05 99.5% SLO 保护
- **拒绝的替代方案**：①固定窗口限流（突发流量易丢消息）②无限重发（拥塞 + SLO 失效）
- **影响范围**：M-008、监控告警 M-017
- **相关 ADR**：ADR-002
- **来源**：[TD推断:CE-005 修复]

## ADR-009 [DNS Pinning 跨对象保持]
- **状态**：已接受
- **决策内容**：DE-011 `dns_pinning_enabled=true`；M-013 实现域名级缓存 Resolver，跨对象生命周期保持 IP；HTTP 302 重定向后重新校验
- **决策理由**：①CE-007 跨对象失效导致 SSRF ②BR R-015/R-016 SSRF 防护多层 + IPv6 链路本地禁用
- **拒绝的替代方案**：①仅 yarl 单对象 pinning（已证不足）②全局禁用重定向（破坏 sse/http 正常功能）
- **影响范围**：M-013、DE-011
- **相关 ADR**：ADR-006
- **来源**：[TD推断:CE-007 修复 + 调研报告 S-052]
