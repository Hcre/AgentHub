## 2. 详细问题

### I-01 🔴 落地目标是一个不存在的代码库
- **现象**：`06-详细设计/FS-MCP` 与 `07-文件框架/*` 把所有代码落进 `agenthub/`（Poetry monorepo 根）下的 `src/agenthub/{core,access,application,infrastructure,data,eventbus}`。
- **证据**：计划中 69 个 md 引用 `src/agenthub/`，仅 3 个引用真实 `src/backend/app/`；`src/agenthub/` 在真实代码树中**不存在**。
- **冲突**：真实结构是 `src/backend/app/{api,application,core,domain,infrastructure,schemas}`（5 层洋葱，AR-01）。
- **影响**：按原样落地 = 放弃/重写现有平台。这是最根本的阻断项。
- **修订方向**：把所有模块重新映射到 `src/backend/app/` 的现有 5 层；删除 monorepo/src-layout/eventbus 独立层等设定。

### I-02 🔴 分层语义和方向相反
- **现象**：计划用 "Layer 1 接入(Access) → Layer 2 应用 → Layer 3 基础设施 → Layer 4 数据" 自顶向下编号。
- **冲突**：AR-01 洋葱是 `L1 Infrastructure → L5 Presentation`，依赖方向 `L5→L4→L3→L2←L1`（L1 实现 L2 接口，依赖倒置）。计划的"Layer 1=接入层"与项目的"L1=基础设施"语义正好相反。
- **影响**：即便重命名包名，分层心智模型也对不上，Review 时每个模块都要重新判层。
- **修订方向**：统一采用项目洋葱术语；接入层 = L4 API，应用编排 = L3 Application，MCP 进程/沙箱/客户端 = L1 Infrastructure，实体/绑定 = L2 Domain。

### I-03 🔴 违反 AR-02（新 Agent/能力只加 Adapter）
- **现象**：计划新建 `pool`（进程池 + spawner + 健康 + 回收 + 锁）、`sandbox`（多 backend）、独立 `eventbus` 等，形成一套与现有 `AgentRuntime`/`LLMAdapter` 平行的运行时。
- **冲突**：现有已有 `claude_code_runtime.py`/`opencode_runtime.py`/`pi_agent_runtime.py` + `claude_adapter.py`，AR-02 要求扩展走 Adapter。
- **修订方向**：MCP 注入应作为现有 CLI Adapter 的一个能力扩展（向 Runtime 进程注入 MCP 配置 + 转发 stdio/sse/http），不另起运行时与进程池。

### I-04 🔴 技术栈漂移
- **现象（按引用文件数）**：Vault 29 · cgroup 40 · gRPC 20 · iptables 20 · Saga 23 · structlog 16 · OpenTelemetry 9 · Poetry 8 · Kubernetes 5。
- **冲突**：真实栈 = FastAPI app + `requirements.txt`/`pyproject.toml`(pip) + Redis + docker-compose + 既有 alembic。无 Poetry monorepo、无 gRPC/protobuf、无 Vault、无 K8s。
- **修订方向**：删除上述栈；密钥用现有配置/环境注入，日志用项目现有 logger，部署沿用 `src/docker/docker-compose.yml`。

### I-05 🔴 范围严重超纲（约 13/22 模块与 MCP 正交）
- **超纲模块**：M-C01 多 OS 沙箱、M-C02 K4 gRPC 安全扫描器（12 规则）、M-C04 DNS pinning、M-C05 network ACL（iptables/ipset）、M-C06 SSRF guard、M-C07 Vault secret transit、M-A03 webhook 验签（github/gitlab/bitbucket）、M-A04 分布式 cron + leader 选举、M-B02 进程池、M-C09 ACL 迁移 Saga 等。
- **冲突**：当前处于 **MVP 收尾冲刺**（commit `dcc6fff`），目标是"保答辩 3min Demo 跑通"。这些是生产化/平台化基础设施，远超本期。
- **修订方向**：把以上全部移入"下期/生产化"清单；本期只保留 MCP 产品主链路。

### I-06 🟠 部分组件本机不可运行
- **现象**：`macos_sandbox` / `windows_jobobj` / `linux_cgroup` / iptables / ipset / cgroup v2 pids.max。
- **冲突**：开发与演示在 Windows 11 + Docker Desktop；iptables/ipset/cgroup 无法直接验证，多 OS 沙箱无法在单机统一验证。
- **修订方向**：dry-run 验证若保留，先用单一 Docker 容器 + 资源限额（compose 层）即可，删除 OS 级沙箱矩阵。

### I-07 🟠 PRD 内部自相矛盾
- **现象**：PRD V1.3 §5 B-11 明确"不做 OpenTelemetry，内部 trace_id 即可"；但 `FS-MCP` 写 `core/tracing.py # OpenTelemetry SDK`，05-技术架构有 9 文件引用 OTel。
- **修订方向**：以 PRD 边界为准，删除 OTel；可观测仅保留 trace_id 贯穿。同时全量复查"不做清单 B-01~B-13"与下游设计的一致性。

### I-08 🟠 与既有 MCP 计划重复且口径不一
- **现象**：roadmap §十已有"MCP 功能 v1"，代码库对齐：**3 张表**（`mcp_servers`/`workspace_mcp_installations`/`agent_mcp_bindings`）、**8+2 端点**、**3 页 + 1 Tab**、复用现有 CLI Adapter。
- **冲突**：本计划是 **30 实体 / 22 模块 / 新仓**，与 §十 既不同名（如 `user_mcp_installations` vs `workspace_mcp_installations`）也不同量级。
- **附注**：§十 链接的 `docs/plan/MCP功能PRD.md` / `MCP功能计划_v0.md` 当前**已不在磁盘**（疑被本 `MCP接入/` 目录取代），需在修订时明确"单一权威"。
- **修订方向**：二选一并保留单一权威；推荐以 §十 工程口径 + 本目录 PRD 需求口径合并。

### I-09 🟡 07 代码框架不可直接复用
- **现象**：桩文件以巨型 docstring 头为主（如 `market/services.py` 158 行中约 120 行是注释头），业务逻辑为空；且 `from agenthub.* import ...` 引用不存在的包。
- **修订方向**：不要把 `07-文件框架/*/src/` 直接拷进仓库；可把其中**接口契约/方法清单**作为实现时的设计参考。

### I-10 🟡 数据模型/迁移与现有 alembic 不衔接
- **现象**：计划用 `migrations/`（新 alembic env）+ Poetry。真实仓库已有 `src/backend/alembic/versions/0001~0005`。
- **修订方向**：新表迁移续在现有 alembic 链上（0006+），表名/字段与 §十 口径统一，先改 `docs/specs/03-data-model` 再迁移（CR-03 + PR-09）。

### I-11 🟡 未走接口冻结/SPEC 同步红线
- **现象**：计划自带 API/IC 契约，但未对齐 `docs/specs/04-commands` 与 `docs/specs/04c-adapter-interface`，也未经 PR-01 两人 Review 冻结。
- **修订方向**：修订后，把最终端点写入 `docs/specs/04-commands` 冻结（PR-01）→ 再实现；架构改动同步 `docs/specs/01-architecture`（PR-09）。

### I-12 🟢 计划体量超出当前维护能力
- **现象**：8 棒流水线 + 22 模块 × 5 文档（API/FC/FDR/FF/FH）+ 30 实体 + 132 异常，单 MCP 特性产出近百份文档。
- **修订方向**：修订版按 §十 的 4 阶段节奏裁剪文档密度，避免规范红线（D 系列）与维护负担。

## 4. 建议的修订后目标范围（供你定稿参考）

落在真实 `src/backend/app/` 洋葱上，对齐 roadmap §十：

- **L2 Domain**：MCP 实体 + 绑定实体（3 表对应的领域模型）。
- **L1 Infrastructure**：3 张表 SQLAlchemy 模型 + alembic 0006 迁移；MCP 注入能力挂到现有 CLI Adapter。
- **L3 Application**：market（列表/搜索/详情）、install（安装/卸载幂等）、binding（绑定/解绑）、create（stdio/sse 提交 + 模板 + 简化 dry-run）服务。
- **L4 API**：8+2 端点，kebab-case + `{error:{code,message}}`（AP-01~07），**先冻结 `docs/specs/04-commands`（PR-01）**。
- **L5 Presentation**：`/mcp-market` 列表/详情、`/mcp-create`、Agent「MCP 接入」Tab。
- **工具调用事件**：复用现有 WS 通道上报 tool_call_request/response/progress/error。
- **下期**：沙箱矩阵、K4 扫描、SSRF/DNS/ACL、Vault、cron/webhook、SDK Adapter、Codex/Trae。
