## AR-001 [F-012 "标准 MCP 协议" 描述歧义]

- **PRD 原文**: "F-012 注入内容遵循 MCP 2025-06-18 规范 `initialize`/`tools/list` 协议"
- **歧义类型**: 需PM澄清
- **歧义描述**: "标准 MCP 协议"是否指各 Runtime 都支持的标准 flag？还是各 Runtime 私有 CLI + L4 翻译？
- **消除方式**: 调研报告 R-002 验证三 Runtime 均无统一 flag
- **结果**: [调研报告:S-056] 澄清为"调用各 Runtime 私有 CLI 命令 + L4 翻译层"
- **来源**: [调研报告:S-056, S-057]

## AR-002 [F-021 dry-run 误报率 2% 可行性]

- **PRD 原文**: "S-03 dry-run 沙箱验证误报率 ≤ 2%"
- **歧义类型**: 需PM决策
- **歧义描述**: 业界基线 15%，2% 是否可行？
- **消除方式**: 调研报告 R-008 验证 2% 需 LLM 增强
- **结果**: [调研报告:S-058] MVP 接受 10%，3 个月内优化至 2%
- **来源**: [调研报告:S-058, R-008]

## AR-003 [F-008 50 历史版本上限是否可调]

- **PRD 原文**: "F-008 同一 mcp_name 最多保留 50 个历史版本"
- **歧义类型**: 可推断消除
- **消除方式**: 50 是默认值，可配置
- **结果**: [调研报告:S-060] 追加"50 个历史版本上限可通过配置调整，默认 50"
- **来源**: [调研报告:S-060]

## AR-004 [F-014 WebSocket 投递率目标 99.5% 实现细节]

- **PRD 原文**: "F-014 投递成功率 ≥ 99.5%"
- **歧义类型**: 可推断消除
- **消除方式**: 调研报告 S-054 给出 ack + 5s 重发路径
- **结果**: [调研报告:S-054] "需 WebSocket 客户端加 ack 回执 + 服务端去重表，5s 未 ack 触发重发"
- **来源**: [调研报告:S-054, S-055]

## AR-005 [F-016 IM 取消响应 2s 是否含网络延迟]

- **PRD 原文**: "F-016 取消请求 2s 内到达 Runtime"
- **歧义类型**: 可推断消除
- **消除方式**: 2s 是端到端 SLA 含网络
- **结果**: [SA推断:依据 — 业界 SRE 标准] 2s = 客户端到 Runtime 端到端，含 WS 推送
- **来源**: [SA推断:依据 — 业界 IM 取消响应惯例]

## AR-007 [F-022 5 模板上游仓库 PostgreSQL 替代]

## AR-008 [F-019 sse/http 是否含旧 HTTP+SSE]
