# AgentHub 用户部署方案对比

## 核心需求
- 对普通用户友好，不要求懂命令行
- Agent 能直接读写本地文件
- 项目结构不冗杂

---

## 方案 A：Electron 桌面应用（体验最好，开发最重）

**用户怎么用**：下载安装包 → 双击安装 → 启动 → 自动打开界面 → 开始和 Agent 聊天

```
┌─ Electron 壳 ──────────────────────┐
│  ┌─ 前端 (React) ────────────────┐ │
│  │  Web UI                        │ │
│  └────────────────────────────────┘ │
│  ┌─ 后端 (FastAPI 子进程) ───────┐ │
│  │  API + 代理                     │ │
│  │  SQLite 数据库                  │ │
│  │  进程管理 (spawn claude/pi)     │ │
│  └────────────────────────────────┘ │
└────────────────────────────────────┘
```

| 维度 | 评级 |
|------|:---:|
| **用户友好度** | ⭐⭐⭐⭐⭐ 一个安装包搞定 |
| **文件访问** | ⭐⭐⭐⭐⭐ 原生文件系统 |
| **开发复杂度** | ⭐⭐ 需要 Electron + 打包流水线 |
| **体积** | ~200MB (含 Python runtime) |
| **跨平台** | Win/Mac/Linux 各打一个包 |
| **更新** | 自动更新器 |

**代价**：需要搭建 Electron 打包流水线（electron-builder），处理 Python runtime 嵌入，签名证书。

---

## 方案 B：一键启动脚本（开发最轻，体验中等）

**用户怎么用**：下载文件夹 → 双击 `启动.bat` → 浏览器自动打开 → 开始用

```
下载的文件夹/
  ├── 启动.bat             ← 管理员运行，自动检查环境
  ├── backend/             ← Python FastAPI
  ├── frontend/dist/       ← React 构建产物
  ├── python/              ← 嵌入式 Python（自带，用户不用装）
  └── data/                ← SQLite 数据库
```

`启动.bat` 做的事：
```batch
1. 检查 Python → 有就用系统的，没有就用自带的嵌入式 Python
2. pip install -r requirements.txt（首次）
3. 启动 backend 后台
4. 打开浏览器 http://localhost:8000
```

| 维度 | 评级 |
|------|:---:|
| **用户友好度** | ⭐⭐⭐ 需双击一个文件 |
| **文件访问** | ⭐⭐⭐⭐⭐ 原生，backend 跑在宿主机 |
| **开发复杂度** | ⭐⭐⭐⭐⭐ 一个脚本 + 嵌入式 Python |
| **体积** | ~80MB |
| **跨平台** | 各平台写对应脚本 (.bat / .sh) |
| **更新** | 手动下载覆盖 |

**代价**：用户需要信任 `.bat` 脚本，Windows Defender 可能报毒。首次启动较慢（装依赖）。

---

## 方案 C：npm/npx 一键启动（对前端开发者最熟）

**用户怎么用**：
```bash
npx agenthub start
# → 自动安装 → 启动后端 → 打开浏览器
```

或：
```bash
npm install -g agenthub
agenthub start
```

| 维度 | 评级 |
|------|:---:|
| **用户友好度** | ⭐⭐ 仍需装 Node.js |
| **文件访问** | ⭐⭐⭐⭐⭐ 原生 |
| **开发复杂度** | ⭐⭐⭐⭐ npm 包发布流水线 |
| **体积** | ~50MB |
| **跨平台** | ✅ Node.js 天然跨平台 |
| **更新** | `npm update -g agenthub` |

**代价**：要求用户有 Node.js。适合技术用户，不适合普通人。

---

## 方案 D：Docker 桌面应用（Docker 用户最熟）

**用户怎么用**：
```bash
docker run -p 8000:8000 -v D:\projects:/workspace ghcr.io/agenthub/app
```

或 docker-compose up。

| 维度 | 评级 |
|------|:---:|
| **用户友好度** | ⭐⭐ 需装 Docker |
| **文件访问** | ⭐⭐ 需 mount，体验差 |
| **开发复杂度** | ⭐⭐⭐ 一个 Dockerfile |
| **体积** | ~500MB |
| **跨平台** | ✅ Docker 跨平台 |
| **更新** | `docker pull` |

**不推荐**。Docker 对普通人门槛太高，且文件访问体验是我们反复踩坑的。

---

## 取舍建议

| 你的优先级 | 推荐方案 |
|-----------|---------|
| **体验至上，愿意投入** | 方案 A（Electron） |
| **快速上线，已满足** | 方案 B（启动脚本） |
| **面向开发者** | 方案 C（npm/npx） |
| **不考虑** | 方案 D（Docker） |

**我的建议**：先 B 后 A。用方案 B 快速验证产品（改动最小），产品验证通过后再投入 Electron 打包提升体验。两个方案共享同一份 backend 代码，前端也只需调整入口。
